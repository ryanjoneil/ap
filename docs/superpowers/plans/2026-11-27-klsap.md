# k-best assignments (`klsap`) and `Fix` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `Remove` with `Fix(u, v, value)` in `lsap`, `lbap` and `mcm`, then build `klsap`, which ranks the k best assignments with Murty's method on top of `lsap`, and its CLI `cmd/klsap`.

**Architecture:** `Fix(u, v, true)` requires an edge. In `lsap` both kernels keep the required pair assigned and exclude its row and column from every later search, at O(n) cost and with no change to the dense inner loop. `klsap` keeps at most k − r solved `lsap` subproblems in a bounded priority queue, and splits each popped one by `Copy`, `Fix` and `Assign`. `lbap` and `mcm` implement `Fix(true)` by forbidding the competing edges.

**Tech Stack:** Go 1.27, standard library only.

**Spec:** `docs/superpowers/specs/2026-11-27-klsap-design.md`

## Global Constraints

- Branch `v0.6-klsap`, cut from `v0.6`. The PR targets `v0.6`, not `master`.
- Signature, all three solvers: `Fix(u, v int, value bool)`. `true` requires edge (u, v), `false` forbids it. `Remove` is deleted everywhere.

## Review Focus

1. Requiring an edge that is already assigned: the next `Assign` returns the same assignment and cost without re-solving. Murty's split relies on this for every edge it requires. Task 1 pins it.
2. `Fix` before the first `Assign`, and on a fresh `Copy` whose sparse scratch space isn't allocated yet: the requirement must survive allocation. Task 1 pins it.
3. `ReducedCost` after a requirement: 0 for the required edge, false for every other edge in its row and column. After the dual prices move, those edges can have negative reduced costs, so reporting them would mislead callers who filter on reduced cost. Task 1 pins it.
4. `int8` costs near the margin with random requirements: `Assign` either matches brute force or returns `ErrOverflow`. Setting a required row's dual price is a new place where a price changes. Task 1 pins it.
5. `klsap` with n = 1, and `Next` after the ranking ends: one assignment, then `ErrInfeasible` on every later call, never a panic. Task 3 pins it.

**Interfaces:**
- Produces: `func (a *LSAP[T]) Fix(u, v int, value bool)`. `kernel[T]` replaces `remove(u, v int)` with `fix(u, v int, value bool)`.

**Kernel state, both kernels.** `fixCol []int` (row → required column, or −1) and `fixRow []int` (column → required row, or −1), both nil until the first `Fix(…, true)`, so that `Copy` and the existing benchmarks are unaffected when nothing is required. `Copy` clones them. A conflict sets a sticky flag (dense: a new `conflict bool`; sparse: the existing `infeasible`, but only if `overflow` is not already set).

**`fix(i, j, true)`, both kernels:**
1. Out of range, or `fixCol[i] == j`: return.
2. Conflict if `fixCol[i] ≥ 0`, `fixRow[j] ≥ 0`, or the edge is forbidden or missing (dense: `a[i][j] == m`; sparse: `live(i, j) < 0`).
3. Unassign the current mates: row i's column if it isn't j, and column j's row if it isn't i.
4. Assign i to j (sparse: also `rowEdge[i]`), set `u[i] = cost(i, j) − v[j]`, so that the required edge has reduced cost 0, and record `fixCol[i] = j`, `fixRow[j] = i`. |cost| ≤ A and |v[j]| ≤ b, so the subtraction can't overflow. The dense `assign` already rechecks every dual price against the margin; the sparse kernel's margin never changes, so sparse `fix` checks |u[i]| ≤ b itself and sets `overflow` if not.

**`fix(i, j, false)`:** a conflict if `fixCol[i] == j`; otherwise exactly today's `remove`.

**Excluding required rows and columns from the search:**
- Dense `path`: start each search with `uc[j] = false` for required columns, and skip required columns in the O(n) loop that lowers `v[j]` or `pi[j]` by d. Required rows are never reached, since they're only reachable through their required column. The O(n²) reduced-cost loop doesn't change.
- Sparse `augment`: between searches, `dist[j]` is the smallest value of T for every required column, rather than `maxT`. A relaxation `nd < dist[k]` then always fails, so the edge loop doesn't change. A plain −1 is not enough: once the dual prices move, edges into a required column can have negative reduced cost, so nd can be negative. The first loop, which labels the columns adjacent to s without comparing, skips required columns. Set the value when the scratch space is allocated in `assign` (including on a copy) and in `fix` if it already exists. Update the invariant comment on `dist`.
- `reducedCost(i, j)`: false if row i or column j is required by a different edge.
- `assign`: dense checks `overflow` (sticky), then `conflict` (`ErrInfeasible`), then the existing margin recheck. Sparse keeps `infeasible` before `overflow`.

### Task 3: `klsap` (#24)

**Files:**
- Create: `klsap/doc.go`, `klsap/klsap.go` (API), `klsap/murty.go` (split and bounded queue), `klsap/klsap_test.go`, `klsap/example_test.go`, `klsap/bench_test.go`
- Modify: `internal/bruteforce/bruteforce.go`, `internal/bruteforce/bruteforce_test.go`

**Interfaces:**
- Consumes: `lsap.New`, `lsap.NewSparse`, `(*lsap.LSAP[T]).Copy`, `Fix`, `Assign`, `Cost`.
- Produces: the `klsap` API in Global Constraints, and `bruteforce.AllSums(c [][]int64, ok [][]bool) []int64`, the costs of every allowed assignment, sorted ascending (nil if none).

**Semantics:**
- `New` and `NewSparse` return `lsap`'s validation errors wrapped as `fmt.Errorf("klsap: %w", err)`, and `errors.New("klsap: k must be at least 1")` for k < 1. They don't solve.
- `Next` returns the next assignment, as a slice the caller owns, and sets `Cost`. It returns `ap.ErrInfeasible` when no further assignment exists: for an infeasible problem, after the last assignment, and after k assignments. `ap.ErrOverflow` from any `Assign` is sticky. Once `Next` has returned an error, it returns the same error on every later call.
- It isn't safe for concurrent use. The type doc says so.

**Algorithm (Murty 1968), which the signatures don't determine:**

```
node = {a *lsap.LSAP[T] (solved), p ap.Permutation, cost T, free []int, seq uint64}
  free = the rows not yet required, in increasing order.

Next:
  if a sticky error is set, return it; if r == k, set the sticky error to ErrInfeasible and return it
  if r == 0 and the root isn't solved: Assign the root; on error, set it sticky and return it;
     push {root, p, cost, free = 0..n−1}
  else if pending != nil: split(pending); pending = nil; return a sticky error if split set one
  if the queue is empty: set the sticky error to ErrInfeasible and return it
  pop the node with the smallest (cost, seq); r++; set Cost
  if r < k: pending = node
  return a copy of node.p

split(node):  // node.a is reused as the working solver
  w := node.a
  for t, i := range node.free[:len(node.free)−1]:   // the last free row's child is infeasible
      child := w.Copy(); child.Fix(i, node.p[i], false)
      p, err := child.Assign()
      ErrInfeasible → skip; ErrOverflow → set it sticky and stop
      offer {child, p, child.Cost(), free = node.free[t:], seq = next seq} to the queue
      w.Fix(i, node.p[i], true)   // node.p stays optimal for w, so this needs no re-solve
```

The queue holds at most k − r nodes, where r is the number returned so far, including the one being split. Each pop lowers both the size and the capacity by one, so only offers need the check: offering a node to a full queue keeps it only if its (cost, seq) is below the current worst, which is then dropped. The data structure is the builder's choice (the spec leaves it open). A min-max heap, or two heaps, both work. Ties order by `seq`, so the ranking is deterministic.
