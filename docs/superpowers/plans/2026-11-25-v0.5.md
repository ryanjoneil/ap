# v0.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.5 of `ap`. That means:
- the cleaned-up `ap`/`lsap` API;
- sparse `lsap`;
- shared CLI conventions;
- a `matching` solver and an `lbap` solver, each with its own binary;
- benchmark instance generators and an external performance comparison.

**Architecture:** Public types live in `ap`. Everything outside the hot loops lives under `internal/`: integer bounds, sparse graph building, brute-force test oracles, instance generators, CLI plumbing, and the Hopcroft–Karp kernel. Each solver package writes its own dense and sparse kernels over plain slices. Each binary under `cmd/` is a thin `run()` over `internal/cli`.

**Tech Stack:** Go 1.27, standard library only (`math/rand/v2`, `encoding/json`, `flag`, `slices`). golangci-lint v2.15. The external comparison scripts use Python with SciPy and OR-Tools, outside the Go module's build.

**Spec:** `docs/superpowers/specs/2026-11-25-ap-solver-suite-design.md`. Read it before starting any task.

## Global Constraints

- Standard library only. No new `require` lines in `go.mod`.
- Library costs are generic over `ap.Integer`. The CLIs use `int64` internally.
- Constructors return `(*Concrete, error)` and never panic on bad input. They copy their input, so callers' slices are never modified.
- Solve methods return `ap.ErrInfeasible` (`errors.New("ap: no feasible assignment")`) when no feasible assignment exists. A removed or missing edge never appears in a result.
- `Remove(u, v)` is a no-op for a missing, removed, or out-of-range edge.
- `Copy()` returns an independent solver. Changes to either one never affect the other.
- Solvers break ties deterministically, so the same input always gives the same output.
- **Citations:** each package's `doc.go` gives the full reference for every algorithm it implements, plus the book section and algorithm number. Each kernel's doc comment names its algorithm and source. Every knowing departure from a source gets a comment. Check citations against the book's bibliography (`~/Dropbox/Books/Optimization/[2012-SIAM] Burkard et al - Assignment Problems.pdf`, bibliography from p. 327), never from memory.
- **CLIs:**
  - Read one JSON value from stdin and write one JSON object to stdout.
  - A top-level array means dense input; a top-level object means sparse input.
  - `"status"` is `"optimal"` or `"infeasible"`, and both exit 0.
  - Invalid input or a bad flag writes `<binary>: <message>` to stderr, writes nothing to stdout, and exits 1.
  - `-h` exits 0.
- **Sparse JSON:** `{"n": N, "edges": [[u, v, cost], ...]}`. For matching: `{"nu": NU, "nv": NV, "edges": [[u, v], ...]}`.
- **`-scale k`:** each cost becomes `math.Round(cost * k)` as `int64`. Reported costs, dual prices and reduced costs are divided by `k`. Without `-scale`, a non-integer cost is an error whose message contains `-scale`.
- **Tests use keyed fields for `ap` struct literals** (`ap.Edge[int64]{U: 0, V: 1, Cost: 5}`), because `go vet` rejects unkeyed literals of imported struct types.
- **Checks before every commit:** `gofmt -l .` prints nothing; `go vet ./...`, `go test -race ./...` and `GOTOOLCHAIN=go1.27.4 go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0 run ./...` all pass.

## Review Focus

The cases below are implied by the spec but easy to miss, ranked by how likely they are to bite a user. Each has a test in the task that owns the code.

1. **`Copy` independence under copy-on-write.** After `b := a.Copy()`, a `Remove` on either solver must not change the other's costs or results. Tests: Task 4 `TestCopyIndependent`, Task 7 `TestSparseCopyIndependent`, Task 11 `TestCopyIndependent`, Task 13 `TestCopyIndependent`.
2. **Negative and mixed-sign costs in the new kernels.** The dense bug fixed in v0.4 came from exactly this, and sparse `lsap` and `lbap` must handle them correctly. Tests: brute-force tests in Tasks 7 and 13 draw costs from [-10, 10].
3. **A row or column with no edges in sparse input.** This must return `ErrInfeasible` without hanging or panicking. Tests: Task 7 `TestSparseIsolated`, Task 13 `TestIsolated`.
4. **Removing every edge of a row, then solving.** This must return `ErrInfeasible`, and a `Copy` taken before the removals must still solve normally. Tests: Task 7 `TestSparseRemoveWholeRow`, Task 13 `TestRemoveWholeRow`.
5. **Malformed CLI input.** Trailing data, the wrong number of entries in an edge, unknown fields, numbers out of `int64` range, a bad `-scale`, or a non-array/object top level must each exit 1 with a message and no panic. Tests: Task 8 `TestReadCostsErrors` and `TestReadPairsErrors`.

**Dense rules:**
- Rename the existing struct to `dense[T]` and keep the CMT algorithm code unchanged.
- Big-M: `M = n·(maxC − minC) + maxC + 1`, computed with `intmath` checked operations. Any overflow is an error.
- Overflow bound: let `C = max(|minC|, |M|)`. `New` returns an error unless `intmath.FitsScaled(4*(n+1), C)`. Document the rule in `New`'s doc comment.
- `Remove(i, j)` sets the cost to M. A cost equal to M means the edge is removed, since every real cost is below M.
- After solving, if any assigned edge costs M, return `ErrInfeasible`.
- `ReducedCost` returns `(0, false)` for an out-of-range or removed edge.
- Copy-on-write by row:
  - `dense` holds `a [][]T` and `owned []bool`. `New` copies every row and marks them all owned.
  - `copy()` clones the row-header slice and all state vectors, and sets `owned` to all false in **both** the original and the copy.
  - `remove(i, j)` clones row `i` first if it isn't owned.

**Rules:**

- `Cost()` is the sum of the assigned edges' costs.
- `copy()` shares the CSR graph and costs, and clones `removed`, `u`, `v`, `rowMate` and `colMate`. Scratch space is allocated fresh and lazily.

**Algorithm** (the signature and tests don't determine it). Use it in `sparse.go`, with a doc comment citing book §4.4 (Algorithms 4.9–4.10) and Jonker & Volgenant (1987), book ref [408]. Confirm which one the code follows and cite that one.

```
state: u[n], v[n] T; rowMate[n], colMate[n] int (−1 = free); removed []bool per edge (nil until first Remove)
scratch: dist[n] T (MaxOf = unreached), pred[n] int, done []bool (column scanned), touched []int, heap of (dist, col)

init (in NewSparse):
  v[j] = min over edges (i,j) of c(i,j)
  u[i] = min over edges (i,j) of c(i,j) − v[j]
  for each row i: the lowest-index j with c − u − v == 0 and colMate[j] == −1 → match i–j
  any row or column with no edges → mark infeasible (Assign returns ErrInfeasible)

augment(s):                                       // live edge = existing and not removed; rc = c − u[i] − v[j]
  for live (s,j): dist[j] = rc(s,j); pred[j] = s; push (dist[j], j)
  repeat:
    pop min (d, j), ordered by d then j; skip if done[j] or d != dist[j]
    done[j] = true
    if colMate[j] == −1: sink = j; L = d; break
    i = colMate[j]
    for live (i,k) with !done[k]: nd = d + rc(i,k); if nd < dist[k]: dist[k] = nd; pred[k] = i; push
  heap empty without sink → ErrInfeasible
  u[s] += L
  for each done column j ≠ sink: i = colMate[j]; u[i] += L − dist[j]; v[j] −= L − dist[j]
  augment along pred from sink back to s (swap mates)
  reset dist/pred/done only for touched columns

assign: for each free row s: augment(s); return a copy of rowMate
remove(u,v): e = Find(u,v); if e < 0 or removed[e]: return; removed[e] = true; if rowMate[u] == v: free both
```

### Task 13: `lbap` package

**Files:**
- Create: `lbap/doc.go`, `lbap/lbap.go`, `lbap/lbap_test.go`, `lbap/example_test.go`, `lbap/bench_test.go`
- Modify: `internal/conformance/conformance_test.go`

**Interfaces:**
- Consumes: `graph.FromMatrix`/`FromEdges` (Task 5), `bipartite` (Task 10), `bruteforce.MinMax` (Task 4), `instances` (Task 6).
- Produces:
  ```go
  type LBAP[T ap.Integer] struct { /* see rules */ }
  func New[T ap.Integer](costs [][]T) (*LBAP[T], error)
  func NewSparse[T ap.Integer](n int, edges []ap.Edge[T]) (*LBAP[T], error)
  func (a *LBAP[T]) Assign() (ap.Permutation, error)
  func (a *LBAP[T]) Cost() T // bottleneck value after a successful Assign
  func (a *LBAP[T]) Remove(u, v int)
  func (a *LBAP[T]) Copy() *LBAP[T]
  ```
- **Rules:**
  - Validation: empty, non-square, out of range, duplicate. There's no overflow bound, because only comparisons are made.
  - **Rows:** each row's edges are re-sorted by `(cost, column)`. `rowLen[u]` counts the live edges, and removed edges are shifted out past `rowLen[u]`, which keeps the cost order.
  - **Cost levels:** `levels` holds the sorted distinct costs and is immutable.
  - **Threshold test at level index L:** set `end[u] = start[u] +` the number of live edges in row u with cost ≤ `levels[L]` (binary search within the row). Unmatch every row whose mate's edge cost is above `levels[L]`, then run `Maximize`. The test is feasible when the size is n.
  - **`Assign`:**
    - If the current solution is still valid, return it.
    - Otherwise test the top level; if it's infeasible, return `ErrInfeasible`.
    - Binary search for the lowest feasible level in `[lo, top]`. `lo` is the previous optimum's level, since removals never decrease the bottleneck, or 0 the first time.
    - Finish with a test at the found level, so the state holds that level's perfect matching.
  - **`Remove`:** shift the edge out of its row, unmatch u if v was its mate, and mark the solution invalid only if the removed edge was assigned.
  - **`Copy`:** share `levels`; deep-copy the rows, costs, `rowLen`, `end` and state.
- **Citations:**
  - `doc.go`: Garfinkel, *Oper. Res.* 19:1747–1751 (1971), book ref [313]; book §6.2.2, Algorithm 6.1 (Threshold); and Hopcroft–Karp for the feasibility checks.
  - Departure comments: binary search over the distinct cost levels, and warm-starting from the previous matching.
